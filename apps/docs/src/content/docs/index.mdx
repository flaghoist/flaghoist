## Why Flaghoist

<CardGrid>
  <Card title="Runs where you already are" icon="rocket">
    One command deploys it to Cloudflare Workers, where it costs nothing when idle. Or run the same
    server as a container on Render, Fly.io, Railway, a VPS or Kubernetes.
  </Card>
  <Card title="OpenFeature-native" icon="open-book">
    The read API is the OpenFeature Remote Evaluation Protocol (OFREP), so Go, Java, Python, .NET,
    Ruby, Rust and JavaScript read flags through their standard providers.
  </Card>
  <Card title="Your database" icon="setting">
    Flags live in storage you already run: Cloudflare KV, Redis, Postgres or SQLite. A storage
    adapter is four methods if you need another.
  </Card>
  <Card title="Built for a team" icon="approve-check">
    Accounts with four roles, invites, single sign-on with your identity provider, two-factor codes,
    personal access tokens, and an audit log of every change.
  </Card>
</CardGrid>

## The shape of it

Flaghoist has two independent halves:

- **The flag service**, deployed once for your team on your own infrastructure. It keeps flags in
  your storage and serves the OFREP read API, an admin API, and a dashboard at `/admin`.
- **Your apps**, which install an OpenFeature provider and read flags. They never import Flaghoist,
  so moving to another backend later is a one-line change.

Start with the [quickstart](/quickstart/), read how it [fits together](/architecture/), or see how
to [bring in your team](/accounts/).
